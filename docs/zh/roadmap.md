# 扩展方向

[文档索引](README.md) · [English](../roadmap.md) · [架构与设计](architecture.md)

这里整理适用于更大规模研究和部署的可选扩展方向，不代表发布承诺，也不是已经验证的缺陷清单。当前支持的行为以链接的指南为准；开始扩展前，应先核对实现与具体任务需求。

## 跨工作流的可验证复用

CSL 已支持精确匹配并核验结果后复用。其他科学工作流仍由 agent 比较检索到的候选。可以在执行前增加统一检查，比较输入内容、势函数内容、晶胞与边界条件、固定原子、参考构型、科学参数和算法版本。来源文件的 hash 标识字节内容，本身不能证明两次计算等价。

返回候选 run/artifact ID、参数差异、完整性与收敛状态，并记录复用或重新计算的原因。完成状态不自动代表收敛。Coding 若支持经过核验的复用结束路径，也需要在新建沙箱前定义明确的完成契约。用户明确要求重算时，应优先遵从。

参见[项目记忆](project-memory.md)和[扩展开发指南](extension-guide.md)。

## 批量结果的发现能力

为候选检索统一提供 item、帧、约束和参考构型过滤，并补充常用科学术语的中英文别名。对于部分失败的批次，成功 item 必须具有独立验证的输出与精确来源，才能作为复用候选；父批次仍保留实际状态。

检索预览继续保持有界，未展示的候选通过分页和精确查询获取。记录候选被采用或排除的原因，便于区分记录缺失、检索遗漏和科学条件不同，而不必扩大每个 agent 的上下文。

参见[记忆查询工具](project-memory.md#agent-查询工具)。

## Coding 续作与科学检查

当前追加输入已能在同次 invocation 中保留临时工作。持久续作可以导出选定源码、进度和必要失败信息，再将这些快照导入新沙箱。草稿与失败输出必须区别于已验证结果，恢复后的任务仍保留精确输入授权和来源关系。

还可以增加仅针对当前工作区的图像预览、版本化科学配方，以及领域输出检查。现有格式检查和脚本成功退出不能证明科学正确性；数值不变量、单位和输入输出关系需要明确的验证契约。反复使用且稳定的配方可以逐步成为确定性工具。

参见[Coding agent](coding-agent.md)和[工具接入](extension-guide.md)。

## 跨服务进程的资源协调

Coding 和 LAMMPS 准入池目前分别在服务进程内记账。共享调度器或配额存储可以让多个 worker 和两条执行路径共同遵守整机预算，并支持等待时取消和绑定执行所有者的配额释放。

进程树限制仍需单独保障：区分委派 cgroup 的强制限制与采样监测，并定义服务进程退出或子进程脱离后的清理方式。扩展准入时应保留项目所有权规则，防止迟到 worker 在执行已结束后发布结果。

参见[Coding 资源限制](coding-agent.md#进程树资源限制)和[API 执行生命周期](api-and-ui.md)。

## 证据身份与物理单位

新登记的永久 artifact 已保存内容 hash。旧文件的迁移应区分原始登记的摘要与新测得的摘要：核对今天的字节不能证明其历史身份。可以把一致的来源校验扩展到更多专用输入路径，包括执行时实际使用的势函数文件。

外部构型还需要明确的长度单位声明和受控转换。只有来源单位能够确定时，导入坐标的长度上限才能解释为以 Å 为单位的上限。原始物理值应保留，单位转换与显示缩放分别记录。

如果增加更细的文件可见性规则，应统一作用于搜索、handoff、直接读取和工具原文归档。保留策略标签本身不能定义访问权限。

参见[产物与来源](project-memory.md#artifact-manifest-与-provenance)和[分析工具](tools.md)。

## 归档容量与维护

为工具完整输出、运行时 checkpoint 和派生视图增加容量统计与引用追踪。维护策略应先判断记录是否仍被引用，再回收无引用的临时或派生数据；不能只按文件年龄清理。

权威事实、run、结论、科学产物和历史 summary 应继续可用。摘要压缩不能删除这些证据。重建视图、压缩运行时存储和导出项目归档时，都应保留稳定 ID 与精确查找路径。

参见[摘要历史](project-memory.md#历史摘要与查询入口)和[运行时 checkpoint](project-memory.md#runtime-checkpoint)。

## 重连与执行状态展示

更清晰地展示项目占用和执行清理进度，并考虑断线后的有界重连。重连应先查询已有 request ID 与持久结果、取得有效占用，并在允许新任务前等待旧执行退出。不能静默重放科学计算，也不能削弱一个项目只由一个前端占用的规则。

参见[Web API 与界面](api-and-ui.md)。
